# Actividad de Evaluación Continua - Markdown

## Creación de documentación profesional con Markdown

## 1. Objetivo de la actividad

El objetivo de esta actividad es aplicar los conocimientos adquiridos en las clases de introducción y Markdown avanzado para elaborar un documento de documentación técnica de un proyecto ficticio.

Se evaluará la capacidad para utilizar correctamente la sintaxis de Markdown, organizar la información mediante una estructura lógica y aprovechar los elementos de formato avanzado para crear documentación clara, visual y profesional.

## 2. Descripción del ejercicio

Cada alumno deberá elegir o inventar un proyecto tecnológico. Puede tratarse de una aplicación web, un videojuego, una aplicación móvil, una herramienta de productividad, una API o cualquier otro proyecto relacionado con la tecnología.

A partir de esa idea, deberá desarrollar un archivo `README.md` que sirva como documentación principal del proyecto.

El documento deberá incluir los siguientes apartados:

### 1. Presentación del proyecto
- Nombre del proyecto mediante un encabezado H1.
- Descripción general del proyecto.
- Objetivo principal y problema que pretende resolver.
- Una imagen representativa, logotipo o imagen ilustrativa.
- Uso de negritas, cursivas y otros formatos de texto cuando corresponda.

### 2. Índice de contenidos
- Crear una tabla de contenidos con enlaces internos a las diferentes secciones del documento.
- Utilizar una estructura jerárquica coherente de encabezados.

### 3. Características principales
- Describir al menos cinco funcionalidades del proyecto.
- Utilizar listas ordenadas o desordenadas.
- Incluir sublistas cuando sea necesario.
- Utilizar listas de tareas para representar el estado de desarrollo de las funcionalidades.

### 4. Instalación y configuración
- Explicar los pasos necesarios para instalar o configurar el proyecto.
- Utilizar listas ordenadas para describir el procedimiento.
- Incluir al menos un bloque de código con formato específico de lenguaje (por ejemplo, Bash, JavaScript o Python).
- Utilizar código en línea para destacar comandos, variables o elementos técnicos.

### 5. Tecnologías utilizadas
- Crear una tabla con un mínimo de cuatro tecnologías.
- Incluir las siguientes columnas: Tecnología, Versión, Descripción y Uso en el proyecto.
- Aplicar alineación de columnas.
- Utilizar negritas, cursivas o código en línea dentro de las celdas cuando corresponda.

### 6. Arquitectura o funcionamiento
- Explicar brevemente cómo funciona el proyecto.
- Incluir un diagrama realizado con Mermaid. Se puede elegir entre:
  - Diagrama de flujo.
  - Diagrama de secuencia.
  - Diagrama de Gantt.
- El diagrama deberá representar un proceso real relacionado con el proyecto.

### 7. Ejemplos de uso
- Incluir al menos dos ejemplos prácticos de utilización del proyecto.
- Incorporar bloques de código con resaltado de sintaxis.
- Añadir enlaces a documentación externa o recursos relacionados.

### 8. Información adicional
Incluir los siguientes elementos:
- Un bloque de cita con una recomendación, advertencia o nota importante.
- Un bloque colapsable mediante HTML (`<details>` y `<summary>`) que contenga información adicional.
- Al menos un comentario HTML que no aparezca en la visualización del documento.
- Una sección de contacto con enlaces externos o direcciones de correo de ejemplo.

### 9. Elementos visuales y avanzados
- Incorporar al menos dos badges de Shields.io relacionados con el proyecto.
- Utilizar al menos un emoji compatible con GitHub Markdown.
- Utilizar una línea horizontal para separar secciones cuando tenga sentido.
- Incluir un ejemplo de caracteres especiales escapados de Markdown.

## 3. Requisitos de entrega

La entrega se debe hacer en la carpeta `entregas > nombre.apellido > AEC-MD`:
1. Un archivo `README.md` con toda la documentación del proyecto.
2. Los recursos gráficos utilizados, si son archivos externos locales.
3. Una captura de pantalla de la visualización final del documento en el editor o plataforma utilizada.

## 4. Consideraciones importantes

- Se valorará especialmente la correcta aplicación de Markdown y no únicamente la cantidad de elementos utilizados.
- El documento debe tener una estructura coherente y facilitar la lectura.
- Los enlaces y las imágenes deben funcionar correctamente.
- Los bloques de código deben utilizar el lenguaje correspondiente.
- Los diagramas Mermaid deben representar información comprensible y estar correctamente construidos.
- Los elementos HTML deben utilizarse de forma justificada.
- Se permite utilizar proyectos reales o ficticios, siempre que el contenido sea original y esté elaborado por el alumno.
  - En caso de que el proyecto se real, se deben tener todos los permisos para divulgar información sobre dicho proyecto.
- La entrega debe estar correctamente enviada a través de un pull-request en GitHub.
